# Оставшиеся ограничения и работы

## Требуют решения пользователя

1. **Юридические тексты.** Документы в `frontend/src/pages/legal/legal-documents.ts` содержат прямые указания «необходимо указать перед публикацией»: ФИО/адрес оператора, контактный email, срок хранения, фактические сервисы и получателя писем. Сведения не выдумывались, тексты не менялись. Страницы помечены `noindex, nofollow` до подтверждения. Для публикации нужны фактические данные и, вероятно, юридическая правка.
2. **Публикация.** Изменения не публиковались: нет push в `main`, релиза и деплоя. Живой адрес `https://onix-fun.github.io/website/` после изменений не проверялся.
3. **Реальные заявки.** Contact API тестировался только с фейковым emailClient и моковым endpoint. Реальная отправка в Telegram/SES не выполнялась.
4. **Production-конфигурация API.** В репозитории нельзя проверить настройки API Gateway, Smart Web Security, Lockbox, правил лимитирования и почтового провайдера. In-memory лимитер функции — best-effort и per-instance; основная защита должна быть на уровне инфраструктуры.
5. **Репозиторий UI kit.** Отдельный репозиторий `ui-kit/` инициализирован, `origin` указывает на `https://github.com/onix-fun/ui-kit.git`, но коммитов и push не было. Пока удалённый репозиторий не содержит собранное состояние `ui-kit/`, job'ы frontend CI с `actions/checkout` этого репозитория не запустятся.

## Технические ограничения

- **Полевые метрики.** CrUX/RUM недоступны; LCP/CLS измерены только в Lighthouse lab, field INP неизвестен. После деплоя стоит подключить field-мониторинг и подтвердить цели LCP ≤ 2.5 s, CLS ≤ 0.1, INP ≤ 200 ms.
- **Визуальные регрессии.** Базовые снимки сгенерированы в macOS Chromium. В CI используется Linux Chromium; порог `maxDiffPixelRatio: 0.05` компенсирует сглаживание, но при первом прогоне на Linux может потребоваться пересборка эталонов.
- **Зависимости.** После переноса UI kit production-деревья frontend, ui-kit и backend имеют 0 уязвимостей по `npm audit`. Полные деревья dev-зависимостей: frontend — 3 critical (`eslint-plugin-boundaries`, `@boundaries/elements`, `handlebars`) и 9 moderate; ui-kit — 4 high (`histoire`, `@histoire/plugin-react`, `zod`, `@modelcontextprotocol/server`), 5 moderate и 1 low; backend — 0. Это инструменты линтинга и Histoire, не попадающие в production-бандл. Автоисправления не применялись, чтобы не обновлять beta-зависимости Histoire без согласования.
- **Локальный Node.** Backend-тесты запускались на Node v20.19.4 с предупреждением AWS SDK; CI настроен на Node 22. Histoire требует Node ≥22.12.0, поэтому локально `story:build` проходил с предупреждением `EBADENGINE`, а dev-сервер не поднимался.
- **Сравнимость Lighthouse.** Baseline измерялся в HeadlessChrome 157; во время работы системный Chrome обновился до 158, и Lighthouse стал использовать обычный headless-режим с другими метриками. Финальные замеры после UI kit выполнены через `chrome-headless-shell` 154 в том же мобильном профиле; это лабораторные числа, не полевые данные.
- **Локальная ссылка на пакет.** Frontend подключает `@onix/ui-kit` через `file:../ui-kit`. Локально это symlink в `node_modules`; в CI/README важно собирать пакет до установки frontend, иначе `dist/` будет отсутствовать.
- **SPA fallback.** `frontend/public/404.html` содержит `/website`, что совпадает с текущим GitHub Pages base. При смене `VITE_BASE_PATH` или домена нужно синхронно обновить `404.html`, `robots.txt` и `sitemap.xml`.

## Что сделано, но требует подтверждения после публикации

- Deep link `/about`, `/catalog/object-01`, `/digital/digital-01` через GitHub Pages 404 fallback.
- Индексация: `robots.txt`, `sitemap.xml`, canonical и OG на боевом домене.
- DoS-защита Contact API в реальной конфигурации шлюза.
- Финальные Lighthouse-оценки на публичном URL с реальным кэшем и CDN.

## Что сознательно не делалось

- Не менялись Home и Header визуально: сравнение хешей и геометрии до/после показало полное совпадение.
- Не менялись публичный контракт Contact API, формулировка согласия и его версия.
- Не добавлялись вымышленные факты, клиенты, метрики, цены и сроки.
- Не выполнялась миграция на Next.js и не добавлялись тяжёлые архитектурные зависимости.
- Не делались коммиты и push ни в родительский репозиторий, ни в `ui-kit`; не создавались remote-ветки и релизы.
- Не отключались средства безопасности и не изменялись системные политики.
